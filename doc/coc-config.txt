FLOAT CONFIGURATION
							*coc-config-float*

Used by `floatFactory.floatConfig`, `suggest.floatConfig`,
`diagnostic.floatConfig`, `signature.floatConfig`, and `hover.floatConfig`.
The following properties are supported:

	- "border": Set to `true` to enable the border.
	- "rounded": Use rounded borders when border is `true`.
	- "highlight": Background highlight group of the float window, default:
	  `"CocFloating"`.
	- "title": Title text used by the float window, default: `""`.
	- "borderhighlight": Border highlight group of the float window, default:
	  `"CocFloatBorder"`.
	- "close": Set to `true` to draw close icon.
	- "maxWidth": Maximum width of the float window, including the border.
	- "maxHeight": Maximum height of the float window, including the border.
	- "winblend": Set the 'winblend' option of the window (Neovim only),
	  default:
	  `0`.
	- "focusable": Set to false to make the window not focusable (Neovim
	  only).
	- "shadow": Set to true to enable shadow (Neovim only).
	- "position": Controls how floating windows are positioned. When set
	  to `'fixed'`, the window will be positioned according to the `top`,
	  `bottom`, `left`, and `right` settings. When set to `'auto'`, the
	  window follows the default position.
	- "top": Distance from the top of the editor window in characters.
	  Only takes effect when `position` is set to `'fixed'`, and is
	  ignored if `bottom` is set.
	- "bottom": Distance from the bottom of the editor window in
	  characters. Only takes effect when `position` is set to `'fixed'`.
	  Takes precedence over `top` if both are set.
	- "left": Distance from the left edge of the editor window in
	  characters. Only takes effect when `position` is set to `'fixed'`,
	  and is ignored if `right` is set.
	- "right": Distance from the right edge of the editor window in
	  characters. Only takes effect when `position` is set to `'fixed'`.
	  Takes precedence over `left` if both are set.

LANGUAGESERVER
							*coc-config-languageserver*

	Dictionary of language servers: the key is the ID of the corresponding
	server, and the value is the configuration of the language server.
	Default: `{}`.

	Properties of a language server configuration:

	- "enable": Set to `false` to disable that language server.

	- "filetypes": Supported filetypes; add `*` to the array for all
	  filetypes. Note: this is required to start the language server. Make
	  sure your filetype is the one expected by the
	  `:CocCommand document.echoFiletype` command.

	- 'maxRestartCount': Maximum restart count when server closed in the
	  last 3 minutes, defaults to `4`.

	- "additionalSchemes": Additional URI schemes; default schemes include
	  file and untitled. Note: you also have to set up Vim to provide
	  content for custom URIs.

	- "cwd": Working directory used to start the language server; Vim's
	  cwd is used by default.

	- "env": Environment variables for child process.

	- "settings": Settings for the language server, received on server
	  initialization.

	- "trace.server": Trace level of the communication between server and
	  client, shown in the output channel. Open the output channel with
	  `:CocCommand workspace.showOutput`.

	- "stdioEncoding": Encoding used for stdio of child process.

	- "initializationOptions": Initialization options passed to the
	  language server (deprecated).

	- "rootPatterns": Root patterns used to resolve the rootPath from the
	  current file.

	- "requireRootPattern": If true, the server isn't started when no root
	  pattern is found.

	- "ignoredRootPaths": Absolute root paths that the language server
	  should not use as rootPath; takes priority over rootPatterns.

	- "disableDynamicRegister": Disable the dynamic registerCapability
	  feature for this language server to avoid duplicate feature
	  registration.

	- "disableSnippetCompletion": Disable the snippet completion feature
	  for this language server.

	- "disabledFeatures": Disable features for this language server;
	  valid keys: >

	  ["completion", "configuration", "workspaceFolders", "diagnostics",
	  "willSave", "willSaveUntil", "didSaveTextDocument",
	  "fileSystemWatcher", "hover", "signatureHelp", "definition",
	  "references", "documentHighlight", "documentSymbol",
	  "workspaceSymbol", "codeAction", "codeLens", "formatting",
	  "documentFormatting", "documentRangeFormatting",
	  "documentOnTypeFormatting", "rename", "documentLink",
	  "executeCommand", "pullConfiguration", "typeDefinition",
	  "implementation", "declaration", "color", "foldingRange",
	  "selectionRange", "progress", "callHierarchy", "linkedEditing",
	  "fileEvents", "semanticTokens"]
<
	- "languageIdMap": Map of filename to languageId used when the
	  document is opened for this language server, which allows sending
	  a languageId different from the filetype to a specific server,
	  e.g. `{"application.yml": "spring-boot-properties-yaml"}`. The key
	  can be a file name or an absolute path. Note the languageId
	  affects only the documents opened for this language server.

	- "formatterPriority": Priority of this languageserver's formatter.

	- "revealOutputChannelOn": Configure the message level at which the
	  output channel buffer is shown.

	- "progressOnInitialization": Enable progress reporting during
	  language server initialization.

Language server started with a command: ~

	Additional fields for a command-based language server:

	- "command": Executable program name in $PATH, or the absolute path of
	  the executable used to start the language server.

	- "args": Command line arguments of the command.

	- "detached": Detach the language server when true.

	- "shell": Use a shell for the server process. Default: `false`.

Language server started with a Node module: ~

	Additional fields for a language server started by a Node module:

	- "module": Absolute filepath of the JavaScript file.

	- "args": Extra arguments used when forking the JavaScript module.

	- "runtime": Absolute path of the node runtime; coc.nvim's node
	  runtime is used by default.

	- "execArgv": ARGV passed to node on fork, normally used for
	  debugging. Example: `["--nolazy", "--inspect-brk=6045"]`.

	- "transport": Transport kind used by the server; can be 'ipc',
	  'stdio', 'socket', or 'pipe'. 'ipc' is used by default
	  (recommended).

	- "transportPort": Port number used when the transport is 'socket'.

Language server using an initialized socket server: ~

	- "port": Port number of socket server.

	- "host": Host of the socket server; defaults to `127.0.0.1`.

MCP
							*coc-config-mcp*

Configurations of the built-in MCP (Model Context Protocol) socket server,
which lets agents like Codex connect to the running coc.nvim instance through
the `coc-mcp` stdio bridge.

"mcp.autoStart"				*coc-config-mcp-autoStart*

	Auto start the MCP socket server when coc.nvim starts. When enabled,
	coc.nvim listens on a loopback socket and writes the connection info
	(port and per-start token) to `~/.coc/mcp/coc-<pid>.json` (keyed by
	the vim pid, so a coc.nvim restart rewrites the same file).

	When disabled, the server can still be started manually with
	`:CocCommand mcp.start`.
	The server also restarts automatically after `:CocRestart` when it was
	running before the restart.

	Default: `false`

"mcp.host"				*coc-config-mcp-host*

	Host the MCP socket server binds to. Only loopback is supported.

	Default: `"127.0.0.1"`

"mcp.port"				*coc-config-mcp-port*

	Port of the MCP socket server. `0` picks a random free port; the
	active port is written to `~/.coc/mcp/coc-<pid>.json`.

	Default: `0`

"mcp.transport"				*coc-config-mcp-transport*

	Socket transport of the MCP server: `"auto"` (default) uses a
	per-process Unix socket under `~/.coc/mcp` on macOS/Linux and
	loopback TCP on Windows, so no local TCP port is exposed where the
	platform supports it; `"tcp"` forces loopback TCP; `"unix"` forces a
	Unix socket.

"mcp.authRequired"			*coc-config-mcp-authRequired*

	Require the per-start random token (`coc/auth`) before an MCP
	connection is accepted. Disable only for trusted local debugging.

	Default: `true`

"mcp.authClientPublicKey"		*coc-config-mcp-authClientPublicKey*

	Optional PEM public key (SPKI) of the MCP client (the `coc-mcp`
	bridge). When set, clients must prove possession of the matching
	private key by signing a server-issued nonce (`coc/challenge`) in
	place of the per-start token. This is required for the bridge's
	`--connect` mode (SSH-forwarded ports), where the token-bearing
	discovery file must not leave the remote host. Generate a keypair with
	`node bin/coc-mcp.js --generate-key`, put the public key here and the
	private key in the bridge's `COC_MCP_AUTH_KEY_FILE` environment
	variable (a path to a PEM file). Empty (default) keeps the token-only
	flow.

"mcp.maxClients"			*coc-config-mcp-maxClients*

	Maximum concurrent MCP client connections.

	Default: `4`

"mcp.frameMaxBytes"			*coc-config-mcp-frameMaxBytes*

	Maximum size of a single MCP JSON-RPC frame in bytes.

	Default: `16777216`

"mcp.timeout"				*coc-config-mcp-timeout*

	Timeout in milliseconds for MCP tool calls. `0` disables the timeout.

	Default: `5000`

"mcp.readTimeout"			*coc-config-mcp-readTimeout*

	Timeout in milliseconds for read-only MCP tool calls (LSP queries such
	as hover, references or workspace symbols), which are typically slower
	than mutating operations. `0` disables the timeout. Agents cannot
	override these timeouts.

	Default: `15000`

"mcp.idleTimeout"			*coc-config-mcp-idleTimeout*

	Close MCP sessions idle for this many milliseconds. `0` disables the
	idle timeout.

	Default: `0`

"mcp.maxRequestsPerSecond"		*coc-config-mcp-maxRequestsPerSecond*

	Maximum number of JSON-RPC requests per second per MCP session.
	`0` disables the rate limit.

	Default: `60`

"mcp.maxConcurrentRequests"		*coc-config-mcp-maxConcurrentRequests*

	Maximum number of LSP requests MCP tools may send to a single
	language server at the same time. Extra requests wait in a per-service
	queue until a slot frees up, so several MCP clients cannot overwhelm
	one language server. Different servers have different capacity; tune
	per setup. `0` disables the limit; abandoned requests are still tracked
	as stuck and new queries fail fast once 16 accumulate per server.

	Default: `4`

"mcp.languageServiceMap"		*coc-config-mcp-languageServiceMap*

	Map of `languageId` to language server id. When a document's
	languageId has an entry, LSP query tools (hover, definition,
	references, document symbols, rename, ...) send the request directly
	to that server instead of aggregating all matching providers. This
	avoids waiting for the slowest of several attached language servers.
	`lsp/code_actions` always aggregates all matching providers. Server
	ids are shown by `:CocList services`. Leave empty (default) to keep
	the aggregated provider behavior.

	Default: `{}`

"mcp.allowedPaths"			*coc-config-mcp-allowedPaths*

	Glob patterns of paths the MCP server may access. When empty, only
	workspace roots and documents opened in the editor are allowed (the
	temporary directory stays readable for fallback reads). Denied paths
	win over allowed paths.

	Default: `[]`

"mcp.deniedPaths"			*coc-config-mcp-deniedPaths*

	Glob patterns of paths the MCP server must never access; applied
	before `mcp.allowedPaths`.

	Default: `[]`

"mcp.allowedTools"			*coc-config-mcp-allowedTools*

	Whitelist of MCP tool names exposed to agents. Only the tools listed
	here are returned by `tools/list` and callable via `tools/call`;
	everything else is hidden from clients. Default is empty, so no tools
	are exposed until you add the names you want to enable.

	Built-in tools:
	- editor/state
	- document/read, document/read_lines, document/apply_edits,
	  document/write, document/format, document/open
	- workspace/info, workspace/configuration, workspace/search,
	  workspace/files, workspace/apply_edit, workspace/create_file,
	  workspace/rename_file, workspace/delete_file
	- lsp/hover, lsp/signature_help, lsp/definition, lsp/declaration,
	  lsp/type_definition, lsp/implementation, lsp/references,
	  lsp/document_symbols, lsp/workspace_symbols, lsp/diagnostics,
	  lsp/code_actions, lsp/apply_code_action, lsp/rename,
	  lsp/execute_command, lsp/request, lsp/capabilities, lsp/batch

	Tools registered by extensions through `mcp.registerTool()` are
	subject to the same whitelist.

	Default: `[]`
